Introduction

Vous allez effectuer votre Première Analyse en Statistique Descriptive (PASD) avec l'environnement de développement libre et gratuit, RStudio.

Ce travail s'effectuera en groupe de 4 ou 5 étudiants, pour un total de 10 groupes sur la promotion.

Ce projet consiste à réaliser une étude statistique comparative entre deux systèmes agro-alimentaires contrastés — l'Europe occidentale et l'hémisphère sud (par exemple la France et le Kenya) — en s'appuyant sur les données de la FAO.

À l'aide de RStudio et de l'interface Quarto, vous allez concevoir un tableau de bord interactif (Dashboard) qui synthétise les dynamiques de production végétale, l'efficacité des rendements et les enjeux de sécurité alimentaire sur les deux dernières décennies.

Ce travail vous place dans une posture d'ingénieur analyste : il ne s'agit plus seulement de calculer des chiffres, mais de faire parler les données pour mettre en lumière les forces et les vulnérabilités de modèles agricoles différents.

Objectifs

  • Maîtrise de la « data ingénierie » : extraire, nettoyer et structurer des données brutes complexes (gestion des unités, traitement des valeurs manquantes).
  • Application des statistiques descriptives : mobiliser les outils de base (moyennes, écarts-types, coefficients de variation) pour quantifier la stabilité des récoltes et comparer les productivités nationales.
  • Analyse agronomique critique : interpréter les résultats graphiques (courbes de rendement, surfaces cultivées) à la lumière des contextes pédoclimatiques et socio-économiques.
  • Communication scientifique : synthétiser des informations multidimensionnelles dans un outil visuel professionnel et ergonomique.
Visualisation du rendu final

Pour mieux appréhender les attentes, consultez cet exemple de dashboard interactif. Il illustre la manière dont les données brutes de la FAO sont transformées en indicateurs visuels et dynamiques pour l'aide à la décision.

Première analyse

L'objectif est de réaliser une analyse statistique exploratoire (univariée et bivariée) sur l'une des bases téléchargées, pour le binôme de pays de votre groupe. Ce travail doit être effectué exclusivement dans un script R (fichier .R).

Rappel

Les commentaires et tout texte explicatif doivent être précédés du symbole # pour ne pas bloquer l'exécution du code.

Instructions de rédaction :

  • Introduction : courte motivation du choix des pays et des variables sélectionnées.
  • Préparation des données : partie technique, mais commentée.
  • Analyse univariée : pour une variable, pour chaque pays. Interprétez vos résultats.
  • Analyse bivariée : pour deux variables, pour chaque pays. Interprétez vos résultats.
  • Conclusion : interprétation globale de vos résultats.

Remarque

Votre code doit être intelligible pour un tiers. Des commentaires abondants et pertinents sont un critère essentiel de réussite. Explicitez vos choix (pourquoi cette fonction ? pourquoi ce graphique ?) et interprétez vos résultats directement en commentaires : un code qui « parle » est le signe d'une analyse maîtrisée.

Exemple France / Kenya

Pour vous guider, voici une démonstration basée sur le fichier production.csv pour le couple France / Kenya. Cette étude compare la filière blé sur les deux dernières décennies à travers trois indicateurs : surfaces cultivées, rendements à l'hectare et production totale.

Préparation des données

On a besoin du package tidyverse, puis on importe les données.

library(tidyverse)

# IMPORTATION DES DONNEES
raw_fao_prod <- read.csv("data_raw/production.csv")

On réorganise les données pour obtenir un tableau plus facile à manipuler.

# NETTOYAGE DES DONNEES
fao_prod <- raw_fao_prod |>
  select(Zone, Produit, Élément, Année, Unité, Valeur) |>
  mutate(
    Zone    = str_trim(Zone),
    Produit = str_trim(Produit),
    Élément = str_trim(Élément),
    Unité   = str_trim(Unité),
    Produit = case_when(
      Produit == "Maïs" ~ "Mais",
      Produit == "Blé"  ~ "Blé",
      TRUE ~ Produit
    ),
    Élément = case_when(
      Élément == "Superficie récoltée" ~ "Surface",
      Élément == "Rendement"           ~ "Rendement",
      Élément == "Production"          ~ "Production",
      TRUE ~ Élément
    )
  )

On vérifie la cohérence des unités.

table(fao_prod$Élément, fao_prod$Unité)
            ha kg/ha tonnes
Production   0     0    256
Rendement    0   256      0
Surface    256     0      0

On réarrange le tableau pour placer Production, Rendement et Surface en colonnes.

production <- fao_prod |>
  select(Zone, Produit, Année, Élément, Valeur) |>
  pivot_wider(
    names_from  = Élément,
    values_from = Valeur
  ) |>
  rename(
    Pays    = Zone,
    Céréale = Produit
  )

Analyse univariée

On se concentre sur le rendement (kg/ha), indicateur principal de la performance technique.

france_rdt_ble <- production |>
  filter(Pays == "France", Céréale == "Blé") |>
  select(Rendement)

kenya_ble <- production |>
  filter(Pays == "Kenya", Céréale == "Blé") |>
  select(Surface, Rendement, Production)

Le tableau ci-dessous synthétise les indicateurs de tendance centrale et de dispersion.

Le rendement moyen français est environ 3,5 fois supérieur à celui du Kenya. La médiane française est très proche de sa moyenne, suggérant une distribution symétrique ; au Kenya, la variance élevée par rapport à la moyenne indique une instabilité plus marquée des récoltes.

Le boxplot permet de visualiser la stabilité des systèmes.

Le boxplot de la France est situé très haut sur l'axe des ordonnées, témoignant d'une haute performance maîtrisée ; le Kenya présente une boîte plus basse et plus écrasée.

L'histogramme montre si les rendements suivent une distribution normale (cloche) ou s'ils sont instables.

Avec des échelles adaptées, la France possède une distribution relativement régulière, tandis que celle du Kenya est plus irrégulière.

Analyse bivariée

Question d'ingénieur agronome : comment un pays augmente-t-il sa production — en améliorant ses techniques ou en agrandissant ses terres ? On étudie ici les variables Production et Surface.

france_ble_prod_surf <- production |>
  filter(Pays == "France", Céréale == "Blé") |>
  select(Production, Surface)

kenya_ble_prod_surf <- production |>
  filter(Pays == "Kenya", Céréale == "Blé") |>
  select(Production, Surface)

On trace le nuage de points de la production par rapport aux surfaces cultivées, avec une droite de régression.

Le nuage révèle deux stratégies : pour la France la relation est très linéaire (la production suit la gestion des surfaces) ; pour le Kenya les points sont plus dispersés (la surface ne suffit pas à expliquer la production).

FRANCE :
 Équation : y = 16.81 x + -52033200
 Corrélation (R) : 0.918

KENYA :
 Équation : y = 2.71 x + -98698.34
 Corrélation (R) : 0.595

Avec un coefficient proche de 1 (0,92), la France affiche une corrélation quasi-parfaite : le système est prévisible. Le Kenya (0,60) montre une dépendance beaucoup plus aléatoire. La pente française étant plus raide, chaque hectare supplémentaire cultivé en France « rapporte » beaucoup plus de tonnes qu'au Kenya.

De la donnée au Dashboard

Ouvrez le fichier dashboard.qmd déjà présent dans votre OneDrive partagé. Nous allons construire un dashboard pour illustrer votre travail à partir des bases FAOSTAT. L'intérêt de Quarto est triple : fiabilité des résultats (le code est lié aux graphiques), synthèse multidimensionnelle et support d'aide à la décision « prêt à l'emploi ».

Écosystème Quarto

Un fichier Quarto (.qmd) est un document hybride reposant sur trois piliers : l'en-tête YAML (la « carte d'identité » du document), le Markdown (le texte narratif) et les chunks de code R (qui exécutent les calculs et génèrent les graphiques). Quarto compile ces éléments pour produire un dashboard organisé en lignes et colonnes.

En-tête

Éditez le fichier .qmd avec cet en-tête :

---
title: "Première Analyse en Statistique Descriptive"
format:
  dashboard:
    logo: img/Logo_simple_ISTOM_Couleurs_HD.png
    theme: [sandstone, theme/custom.scss]
    nav-buttons: [link-45deg]
    github: https://github.com/votre-depot
fig-width: 10
fig-asp: 0.4
editor_options:
  chunk_output_type: console
---
